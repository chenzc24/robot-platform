# 下游接入与调用说明

本文面向接手源码、把 StrokeReview 作为上游服务调用，或为它接入新算法的开发者。源码包不包含 Python/Node 依赖、模型权重、缓存、桌面可执行文件和任何 API Key。

## 1. 最快运行方式

Windows 开发机需要：

- Python 3.12 或 3.13；
- [uv](https://docs.astral.sh/uv/)；
- Node.js LTS 与 npm；
- 经典 OpenCV 模式不需要模型权重、云端账户或 GPU。

在源码根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1 -SkipModels
```

启动后可访问：

- 网页：`http://127.0.0.1:5173`
- 主 API：`http://127.0.0.1:8000`
- OpenAPI 文档：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/api/health`

停止服务：

```powershell
powershell -ExecutionPolicy Bypass -File .\stop-dev.ps1
```

需要 Lineart、PiDiNet 或 HED 时，去掉 `-SkipModels`。首次运行会下载依赖和模型权重，权重不会写入源码目录。

## 2. 把本项目当作 HTTP 上游调用

### 2.1 查询能力

调用前先查询当前实例实际开放的处理模式：

```powershell
curl.exe http://127.0.0.1:8000/api/v1/capabilities
```

不要在下游写死 provider 列表。响应中的 `provider_options` 会说明模式是否可用、是否依赖模型服务以及是否为云端模式。

### 2.2 提交图片

`POST /api/v1/process` 使用 `multipart/form-data`：

- `file`：PNG、JPEG 或 SVG 文件；
- `parameters`：JSON 字符串，不是单独的 JSON 请求体。

PowerShell 示例：

```powershell
$parameters = '{"provider":"classic","detail_level":50,"cleanup_strength":50,"target_width_mm":210,"pen_width_mm":0.5,"max_strokes":50,"ai_semantic_review":false}'
curl.exe -X POST "http://127.0.0.1:8000/api/v1/process" `
  -F "file=@D:\pictures\input.jpg;type=image/jpeg" `
  -F "parameters=$parameters" `
  -o process-response.json
```

源码内还附带了可运行客户端，它会将完整响应、正式笔触和审核数据分别落盘：

```powershell
uv run --project backend python examples/client/process_image.py `
  D:\pictures\input.jpg `
  --provider classic `
  --output-dir D:\stroke-output
```

如果服务启用了 Basic Auth：

```powershell
uv run --project backend python examples/client/process_image.py `
  D:\pictures\input.jpg `
  --username reviewer `
  --password "服务方提供的访问密码"
```

正式生产调用应使用 HTTPS，并由部署方提供服务地址和应用访问凭据。

### 2.3 响应与坐标

成功响应的关键字段：

- `strokes_document`：下游绘图程序应读取的正式数据，只含判定为 `keep` 的笔触；
- `audit_document`：完整候选、参数、评分、判断原因与警告，用于审核和追溯；
- `diagnostics`：二值线稿和骨架预览，可能为空；
- `processing_id`：本次处理的稳定标识。

`strokes_document.strokes` 已按 `order` 给出正式顺序：主体外轮廓和主要结构优先，身份特征其次，内部细节最后。系统不会为了笔间距离反转坐标方向。坐标为归一化二维坐标，左上角为原点，x 向右、y 向下。实际毫米坐标可按画布最长边换算：

```text
longest_mm = max(canvas.target_width_mm, canvas.target_height_mm)
x_mm = x_normalized * longest_mm
y_mm = y_normalized * longest_mm
```

下游应同时读取 `canvas`，不要假定画布永远是正方形或固定为 210 mm。

当前 JSON Schema 可由运行中的服务获取：

- `GET /api/v1/schema/strokes.json`
- `GET /api/v1/schema/audit.json`

建议下游把 `strokes.json` 当作稳定契约，只依赖已公开字段；审核字段允许以后增加可选信息。

## 3. 接入自己的算法

### 3.1 替换完整“图片到笔触”流水线

复制 `backend/examples/custom_pipeline.py`，实现 `ImageToStrokesPipeline` 协议并返回统一的 `ProcessResponse`。推荐调用 `build_pipeline_response`，由它统一完成画布映射、稳定 ID、审核数据和正式输出。

开发时注册：

```powershell
$env:STROKE_PIPELINE_PLUGINS = "your_package.your_pipeline:create_pipeline"
```

工厂函数返回的 metadata ID 若与内置 ID 相同，会覆盖对应实现；使用新 ID 则会新增一个模式，并自动出现在网页模式列表中。

### 3.2 只替换本地线稿检测模型

复制 `model-service/examples/custom_detector.py`，实现 `LineArtDetectorAdapter` 的 `metadata`、`loaded` 和 `predict`。注册方式：

```powershell
$env:LINEART_DETECTOR_PLUGINS = "your_package.your_detector:create_detector"
```

这种方式只负责“图片转线稿”，后续骨架化、笔触生成、审核和导出仍复用主项目。

更完整的目录、类型和参数说明见 `项目架构与模型替换指南.md`。

## 4. 云端 API 模式的责任边界

千问密钥只配置在运行主后端的服务器上：

```text
DASHSCOPE_API_KEY=<服务端密钥>
QWEN_DASHSCOPE_BASE_URL=https://<业务空间>.cn-beijing.maas.aliyuncs.com/api/v1
QWEN_IMAGE_MODEL=<该业务空间实际部署的模型名>
QWEN_VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_VISION_MODEL=qwen3.8-max-0902
```

请求参数设置 `ai_semantic_review=true` 后，后端会让视觉模型理解主体并按候选稳定 ID 审核笔触；`ai_review_quality` 可取 `economy`、`standard`、`fine`，`max_cloud_review_calls` 限制每张图的视觉审核调用次数。云端只返回语义评分，几何坐标始终由本地流程产生；失败时响应会保留本地结果并在 `semantic_review` 和 `warnings` 中说明回退。

下游客户端不应获得或提交 `DASHSCOPE_API_KEY`。客户端只调用你部署的 StrokeReview 地址；主后端代为调用千问并执行限流、缓存和错误处理。若把源码交给别人由对方自行部署，对方必须使用自己的密钥，或者访问由你控制的在线后端。

不要把 `.env`、用户级环境变量导出、控制台截图或真实密钥放进源码包。`.env.example` 只保留变量名和占位值。

## 5. 独立运行和验证

主后端：

```powershell
cd backend
uv sync --group dev
uv run pytest -q
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端：

```powershell
cd frontend
npm.cmd install
npm.cmd test
npm.cmd run build
```

本地模型服务固定建议使用 Python 3.12：

```powershell
cd model-service
uv sync --python 3.12 --group dev
uv run pytest -q
uv run uvicorn app.main:app --host 127.0.0.1 --port 8010
```

## 6. 源码包内容与限制

源码包包含：主后端、前端、模型服务适配层、桌面启动器、Windows 打包配置、测试、锁文件、示例和文档。

源码包不包含：`.venv`、`node_modules`、模型权重、Hugging Face 缓存、构建目录、桌面 EXE、旧 release、运行日志、用户上传和 `.env`。

项目当前没有单独的 `LICENSE` 文件。向组织外部分发或允许商业二次开发前，项目所有者应先确定本项目自身代码的授权条款，并单独核验所选模型权重的许可证。
