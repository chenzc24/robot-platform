# 千问云端模式接入实施指南

> 文档状态：实施前设计稿，仅描述后续改造方案，本次不包含代码变更。  
> 项目基线：当前仓库的“线稿预处理与笔触审核工具”。  
> 外部信息核验日期：2026-09-01。模型、价格、免费额度和限流会变化，实施与上线当天必须再次核对阿里云百炼控制台和官方文档。

## 1. 目标与边界

在现有“处理算法”下拉框中增加一个 `qwen_cloud` 模式。用户上传 PNG/JPG 后，主后端调用阿里云百炼的千问图像编辑模型生成黑白线稿，再把线稿送入现有 `process_classic`，继续完成二值化、骨架化、分支组合、平滑、审核评分、确定性排序和 `strokes.json` / `audit.json` 输出。

本模式不是一个独立的 PNG 转换网站，也不新增 `/api/v1/lineart`。必须保持当前产品闭环：

```text
React 模式选择
  -> POST /api/v1/process
  -> PipelineRegistry 选择 qwen_cloud
  -> 千问云端图像编辑：原图 -> 黑白线稿 PNG
  -> 下载、验证、解码为 line_mask / intensity confidence
  -> 现有 process_classic：线稿 -> 骨架 -> 笔触 -> 审核
  -> 现有 ProcessResponse
```

以下现有行为不变：

- 正式输出仍是归一化二维连续笔触，不是千问返回的 PNG。
- `strokes.json`、`audit.json`、人工删除/拆分/补画和导出契约不变。
- SVG 仍由注册表自动转到 `svg` 专用流水线，绝不上传到千问。
- 本地 `lineart`、`pidinet`、`hed` 仍走 8010 模型服务；千问不放进该服务。
- 用户原始文件哈希仍写入 `audit.processing.source_sha256`。

## 2. 原指南中不适用于本项目的内容

| 原指南 | 本项目中的正确做法 |
| --- | --- |
| 新建独立 `lineart_service/` | 在现有主后端增加云端 provider，并接入 `ImageToStrokesPipeline` |
| 新建 `main.py` 与 `/api/v1/lineart` | 保持现有 `backend/app/main.py` 和 `/api/v1/process` |
| 最终返回 `FileResponse` PNG | 千问 PNG 只是中间结果，最终返回现有 `ProcessResponse` |
| 单独的 `outputs/` 目录 | 正常请求全程内存处理；如启用缓存，使用专用、可配置的缓存目录 |
| 把千问放在一个新 FastAPI 服务中 | 直接由主后端调用；现有 8010 服务只负责本地 CPU detector |
| 重新安装 FastAPI、Pillow、requests 等 | 当前后端已有 FastAPI、Pillow 和异步 `httpx`；优先复用，不引入同步 `requests` |
| 固定 `qwen-image-edit`、北京地域和 SDK 默认地址 | 模型、地域、Base URL、API Key 全部配置化，且地域必须互相匹配 |
| 用户可完全覆盖提示词 | 第一版只使用服务端受控提示词；不要把通用付费图像编辑器暴露到网页 |
| 云端失败自动降级 | 默认明确报错，不静默回退；避免用户误以为千问已经成功 |
| 固定价格、免费额度和限流写成常量 | 文档仅记录核验日期和参考值，运行时风控使用本地预算/并发配置，发布前查控制台 |

- `model-service/app/*`，除非以后专门决定统一所有 detector 服务。

## 4. Provider 设计

### 4.1 Provider 元数据

建议使用：

```text
id: qwen_cloud
label: 千问云端（联网 · 计费）
description: 阿里云百炼生成线稿后复用本项目骨架与笔触流程；图片会上传云端并按控制台规则计费
input_kinds: raster
requires_model_service: false
selectable: true
```

只有同时满足以下条件时才注册为可选 provider：

- `QWEN_CLOUD_ENABLED=true`
- `DASHSCOPE_API_KEY` 非空
- `QWEN_DASHSCOPE_BASE_URL` 非空且为 HTTPS
- `QWEN_IMAGE_MODEL` 位于服务端允许列表

这样 `/api/v1/capabilities` 会自动把它加入网页下拉框；未配置密钥的开发机、离线桌面包和公开构建不会展示一个必然失败的模式。不要只在 React 的默认列表中硬编码选项。

### 4.2 处理职责

`QwenCloudPipeline.process(request)` 只负责调用 `process_qwen_cloud(...)`。后者负责：

1. 验证请求是 raster。
2. 读取并规范化原图，但保留原始字节用于源哈希和最终画布尺寸。
3. 查询结果缓存。
4. 通过百炼 API 生成一张黑白线稿。
5. 立即下载临时 URL，并在内存中校验和解码。
6. 生成 `line_mask` 和强度代理图。
7. 调用现有 `process_classic(..., line_mask=..., confidence_map=...)`。
8. 写入真实 provider、模型、请求 ID、缓存命中、提示词版本、seed、云端输出哈希和必要警告。

不要让千问直接生成笔触 JSON。生成式模型不适合稳定输出成千上万个精确归一化坐标，也会绕过现有几何清理、评分和审核体系。

## 5. 模型与 API 选择

### 5.1 模型不要写死

原指南中的 `qwen-image-edit` 仍可用，但已不是唯一选择。当前官方图像编辑能力还包括 `qwen-image-3.0`、`qwen-image-3.0-pro`、`qwen-image-edit-plus` 和 `qwen-image-edit-max` 等。实施前用项目真实图片做 A/B 验证，再确定默认模型。

建议的首轮候选：

- 成本/速度基线：`qwen-image-3.0` 或 `qwen-image-edit-plus`。
- 质量基线：`qwen-image-3.0-pro`。
- 兼容对照：原 `qwen-image-edit`。

生产环境优先使用仍受支持的固定快照版本，避免浮动别名升级后结果无预警变化；若只能使用浮动别名，必须把实际模型名和响应信息写入审计，并执行回归样例。

截至核验日，北京地域公开原价并非统一“0.3 元/张”：例如 `qwen-image-edit` 为 0.3 元/输出图，`qwen-image-edit-plus` 为 0.2 元/输出图；`qwen-image-3.0` 的 1K 图像还分别计算输入和输出图像费用。该数字只能作为设计参考，不能写进前端或预算逻辑。详见[官方价格页](https://help.aliyun.com/zh/model-studio/model-pricing)。

### 5.2 API 调用方式

主后端已经依赖异步 `httpx`，因此优先直接调用 DashScope HTTP API，不必为了一个接口引入同步 SDK，也避免修改 SDK 的进程级全局 Base URL。

请求地址由配置的 Base URL 拼接：

```text
{QWEN_DASHSCOPE_BASE_URL}/services/aigc/multimodal-generation/generation
```

请求体的关键语义：

```json
{
  "model": "由 QWEN_IMAGE_MODEL 提供",
  "input": {
    "messages": [{
      "role": "user",
      "content": [
        {"image": "data:image/png;base64,..."},
        {"text": "服务端受控提示词"}
      ]
    }]
  },
  "parameters": {
    "n": 1,
    "watermark": false,
    "seed": 由服务端配置,
    "prompt_extend": false
  }
}
```

注意：不同模型支持的参数不同。调用适配器必须按模型能力表过滤参数，不能把 `size` 或 `prompt_extend` 无条件发给所有历史模型。官方示例、图片约束和参数说明见[千问图像编辑指南](https://help.aliyun.com/zh/model-studio/qwen-image-edit-guide)。

### 5.3 地域配置

API Key、模型可用列表和域名按地域隔离，不能交叉使用。不要在代码中假定“必须北京”或依赖 SDK 默认值。

示例配置：

```dotenv
QWEN_CLOUD_ENABLED=false
DASHSCOPE_API_KEY=
QWEN_DASHSCOPE_BASE_URL=https://your-workspace.cn-beijing.maas.aliyuncs.com/api/v1
QWEN_IMAGE_MODEL=qwen-image-3.0
QWEN_ALLOWED_MODELS=qwen-image-3.0,qwen-image-3.0-pro,qwen-image-edit-plus
```

北京、新加坡及其他支持地域的域名和模型范围，以[地域与接入域名](https://help.aliyun.com/zh/model-studio/regions)为准。API Key 只能存在于主后端环境变量或正式密钥管理系统中，不能进入 React、构建产物、日志、审计 JSON 或桌面安装包。

## 6. 提示词策略

第一版不要提供任意“自定义提示词”输入框。否则用户可以把该模式当作通用付费图片编辑器，输出也更容易偏离笔触任务。

服务端提示词建议版本化，例如 `qwen_lineart_v1`：

```text
将输入图像转换为用于机械臂描绘的纯黑白轮廓线稿。严格保持原图主体、构图、姿势、比例、边界和画布宽高比；不要新增、删除、移动或改写对象。使用纯白背景，仅保留连续、清晰、单色黑色的主体外轮廓和必要内部结构线。去除颜色、光影、渐变、纹理、噪点和背景装饰；忽略非主体文字与水印，不把它们转换为笔触。避免大面积黑色填充、重复轮廓、素描排线和灰色阴影。输出单张 PNG。
```

建议设置 `prompt_extend=false`，减少平台自动扩写引起的创作性改动。`seed` 固定为服务端配置值，但官方只说明相同 seed 有助于“相对稳定”，不能把它当成确定性保证。

如果以后确实要开放补充指令：

- 只能通过 `provider_parameters.prompt_suffix` 追加，不能覆盖核心提示词。
- 限制长度、字符集和用途，并完整写入审核参数。
- 默认关闭，由服务端环境变量显式启用。
- 不允许前端指定模型、Base URL、输出张数或关闭预算保护。

## 7. 输入与输出处理

### 7.1 输入限制

主 API 当前允许 PNG/JPEG/SVG，默认上限 25 MB；官方图像编辑接口的单图上限为 10 MB，并建议宽高位于 384–3072 像素。两层限制不能混为一谈。

千问 provider 内应：

1. 用 Pillow 真正解码图片，不相信上传 MIME。
2. 应用 EXIF 方向并转成 RGB/RGBA。
3. 保持原始宽高比；大图按官方范围缩小。
4. 重编码为 PNG 或高质量 JPEG，使传给百炼的单图低于配置上限。
5. 保留原始图尺寸作为最终 `CanvasSpec.source_width/source_height`。
6. 对过小图片给出质量警告，不应把“官方建议尺寸”误写成硬性 API 下限。

Base64 Data URI 约增加三分之一传输体积，因此还需限制总请求体和内存峰值。不要先把用户原图上传到自建公网对象存储；当前单图场景直接使用 Data URI 更少暴露面。

### 7.2 云端结果下载

官方当前只返回临时 URL，通常 24 小时有效，不支持直接返回 Base64。因此主后端必须在同一请求中立即下载，不能把签名 URL 返回浏览器或写入长期审计。

下载器必须：

- 仅接受 HTTPS。
- 校验主机名符合配置的阿里云 OSS 结果域名规则；不要照抄一组会变化的 bucket 白名单。
- 禁止或严格验证重定向，防止 SSRF。
- 设置连接、读取和总超时。
- 流式限制响应字节数，例如 20 MB。
- 校验 `Content-Type`，再用 Pillow/OpenCV 验证实际图片内容。
- 限制解码后的最大像素数，防止解压炸弹。
- 不记录完整签名 URL；日志只保留请求 ID、模型和状态。

官方对临时 URL 和域名形式的说明见[图像编辑指南的常见问题](https://help.aliyun.com/zh/model-studio/qwen-image-edit-guide)。

### 7.3 转换为现有线图输入

云端 PNG 下载成功后，使用与 `local_model_provider.py` 相同的逻辑：

- 转为单通道灰度。
- 根据边框亮度判断黑线白底或白线黑底。
- Otsu 二值化，得到 `True=线条` 的 `line_mask`。
- 灰度反相得到 0–1 强度代理图。
- 若输出与原图尺寸不同但宽高比一致，缩放到原图尺寸后进入 `process_classic`。
- 若宽高比偏差超过小容差，明确失败，不可静默拉伸人物和构图。

建议把 `_decode_line_map` 从 `local_model_provider.py` 提取为共用模块，避免复制私有函数。

千问没有返回逐像素语义置信度。这里的 `confidence_map` 只表示线条像素深浅，必须在 `audit.warnings` 加入：

```text
qwen_confidence_is_intensity_proxy
qwen_output_is_generative_not_strict_edge_detection
```

## 8. 确定性、缓存与审计

### 8.1 当前契约冲突

本项目声明“同一输入和参数得到相同 ID、顺序和坐标”。生成式云模型即使固定 seed 也不能单独满足这一承诺。并且当前 `process_classic` 的 `processing_id` 主要由原图、参数和 `actual_provider` 计算；若千问重生成了不同线稿却仍得到同一 ID，会造成身份冲突。

### 8.2 必须采用的方案

缓存键至少包含：

```text
SHA-256(
  原始文件字节
  + provider ID
  + 精确模型/部署版本
  + prompt_version 与完整提示词
  + seed
  + 规范化 provider_parameters
  + 云端输入预处理版本
  + 输出参数（尺寸、n、prompt_extend、watermark）
)
```

处理顺序必须先查缓存，再检查/扣减本地调用预算，再请求云端。缓存命中不得产生新费用。

还应计算 `cloud_output_sha256`，并把它作为云端分支的内部 identity material 参与 `processing_id` 和 stroke ID。可通过给 `process_classic` 增加一个可选内部身份盐实现；本地/classic 默认路径保持现状。这样即使缓存清除后模型生成变化，也不会让不同几何共享同一 ID。

生产建议：

- 固定模型快照；浮动别名只用于评估。
- 缓存生成后的 PNG，不缓存临时 URL。
- 单机/桌面模式可使用可配置磁盘目录和 SQLite 元数据。
- 多实例部署使用共享对象存储 + Redis/数据库锁，避免并发重复计费。
- 缓存有保留期和删除策略；缓存被清除后不再承诺逐像素复现。

### 8.3 审计信息

建议值：

```text
requested_provider: qwen_cloud
actual_provider: qwen-cloud:<精确模型或部署名>
source_sha256: 原始上传文件 SHA-256
warnings:
  qwen_request_id:<request-id>
  qwen_prompt_version:qwen_lineart_v1
  qwen_seed:<seed>
  qwen_cache_hit:true|false
  qwen_output_sha256:<sha256>
  qwen_confidence_is_intensity_proxy
  qwen_output_is_generative_not_strict_edge_detection
```

不要写入 API Key、Authorization header、完整 Data URI、原图 Base64、完整签名 URL或含敏感信息的上游响应。

## 9. 错误处理与降级

云端异常应定义为主后端内部异常，不直接泄露 SDK/httpx 堆栈。保持当前前端兼容的字符串 `detail`，不要在未同步修改 `frontend/src/api.ts` 时返回对象型 `detail`。

建议映射：

| 场景 | 主 API 状态 | 用户信息 |
| --- | ---: | --- |
| 云模式未启用或服务端配置不完整 | 503 | 千问云端模式当前不可用 |
| 输入无法解码或云端输入约束不满足 | 422 | 图片不符合千问处理要求 |
| 免费额度用完即停/账户欠费 | 402 | 云端模型额度或账户状态异常，请联系管理员 |
| 百炼限流 | 429 | 云端模型繁忙，请稍后重试 |
| 调用连接失败/响应格式错误/结果下载失败 | 502 | 千问云端处理失败 |
| 上游或下载总超时 | 504 | 千问云端处理超时 |
| 本地日预算或并发保护触发 | 429 或 503 | 已达到本服务的云端调用限制 |

默认不自动回退到 classic。用户明确选择了一个联网且可能计费的模式，静默回退会掩盖配置错误和质量差异。若以后加入可选回退，必须由服务端显式配置，并在 `actual_provider=classic-fallback` 与 warnings 中清楚记录。

付费接口重试要非常保守：连接建立前的明确失败可有限重试；发送后超时属于结果不确定，不自动重发，避免重复计费。429 应把重试交给队列或用户，不在单个网页请求中无限等待。

官方错误码以[百炼错误码](https://help.aliyun.com/zh/model-studio/error-code/)为准，不应只匹配一两个历史字符串。

## 10. 计费、限流和隐私风控

### 10.1 服务端保护

建议环境变量：

```dotenv
QWEN_CLOUD_ENABLED=false
DASHSCOPE_API_KEY=
QWEN_DASHSCOPE_BASE_URL=
QWEN_IMAGE_MODEL=qwen-image-3.0
QWEN_ALLOWED_MODELS=qwen-image-3.0,qwen-image-3.0-pro,qwen-image-edit-plus
QWEN_PROMPT_VERSION=qwen_lineart_v1
QWEN_SEED=20260901
QWEN_CONNECT_TIMEOUT_SECONDS=10
QWEN_READ_TIMEOUT_SECONDS=180
QWEN_TOTAL_TIMEOUT_SECONDS=240
QWEN_MAX_CONCURRENCY=1
QWEN_DAILY_REQUEST_LIMIT=50
QWEN_CACHE_ENABLED=true
QWEN_CACHE_DIR=
QWEN_CACHE_RETENTION_DAYS=30
QWEN_MAX_INPUT_IMAGE_MB=9
QWEN_MAX_RESULT_IMAGE_MB=20
```

说明：

- `QWEN_DAILY_REQUEST_LIMIT` 是本项目自己的硬保护，不等同于阿里云账号限流。
- 多进程/多实例不能用进程内计数器，需要 SQLite/Redis/数据库原子计数。
- 并发锁和预算检查应位于缓存之后、真实调用之前。
- 不允许客户端通过 `provider_parameters` 提高并发、输出张数或切换任意模型。
- 当前产品只有可选 HTTP Basic Auth，没有用户账户配额；公网启用云模式前至少开启 Basic Auth、HTTPS 和反向代理上传限流。

阿里云限流按主账号和模型汇总，充值不会提高 RPM。当前数值应从[官方限流页](https://help.aliyun.com/zh/model-studio/rate-limit)和控制台读取，不写死为“120 RPM”。

### 10.2 控制台保护

测试环境：

- 对支持免费额度的目标模型开启“免费额度用完即停”。
- 配置余额、日账单或预算告警。
- 使用单独业务空间/API Key，便于撤销和观察。

生产环境：

- 是否开启“免费额度用完即停”由可用性目标决定；官方也提示生产环境开启后会在额度耗尽时中断服务。
- 建立正式预算、告警、调用监控和密钥轮换，而不是依赖免费额度。
- 免费额度、有效期和资源包优惠不得作为程序假设。参考[新人免费额度与用完即停](https://help.aliyun.com/zh/model-studio/new-free-quota/)。

### 10.3 用户提示与隐私

网页选择 `qwen_cloud` 时必须明确显示：

- 原图会发送到阿里云百炼处理，不再是纯本地流程。
- 每次未命中缓存的处理可能产生费用。
- 生成式编辑可能改变细节，结果必须人工审核。
- 点击“开始处理”才发起请求；切换下拉框或调整参数不调用云端。

首次调用可要求一次会话级确认。不要在前端硬编码每张价格，因为模型、地域和优惠会变化；显示“按管理员配置和阿里云控制台规则计费”即可。

桌面发行版绝不能内置项目所有者的长期 API Key。若软件分发给第三方，应让用户配置自己的 Key，或只调用由项目方控制、具备鉴权和配额的远端业务后端。

## 11. 前端适配

### 11.1 模式选择

后端注册成功后，前端会通过 `/api/v1/capabilities` 自动获得选项。`defaultProviderOptions` 只是 capabilities 请求失败时的离线回退，不应把未配置的千问放进去。

### 11.2 参数可见性

`qwen_cloud` 的几何后处理仍复用 classic，因此建议：

- 显示 `detail_level`：用于云端输入/输出目标尺寸分档，精确映射需在实现时固定。
- 隐藏 `cleanup_strength`：当前外部 `line_mask` 路径不会完整运行 classic 形态学清理；在统一 mask cleaner 前不要假装生效。
- 显示 `smoothing`、目标宽度、最小线长和四个几何参数。
- 参数说明改为“千问生成线稿后再进行本地骨架与几何处理；原图会上传云端并可能计费”。

第一版不增加模型选择、自由提示词、seed、输出数量等前端控件。这些由管理员环境变量控制。

### 11.3 状态和取消

现有 AbortController 只能取消浏览器等待；请求到达百炼后，取消前端等待不保证取消云端计费。页面文案必须明确这一点。后续如需可靠任务取消，应另行设计服务端作业队列，不能只依赖 Fetch abort。

页头当前写着“本地经典算法与 CPU 深度模型”和 `LOCAL READY`，加入云端模式后需要改为中性文案，避免误导。

## 12. 测试方案

自动化测试绝不调用真实百炼 API，也不读取开发者真实 Key。使用 `httpx.MockTransport` 或等价 mock。

后端至少覆盖：

- 未启用/缺 Key 时 `qwen_cloud` 不出现在 capabilities。
- 启用且配置有效时 provider 注册、排序和 metadata 正确。
- SVG 即使选择 qwen 也仍走 SVG 管线。
- Data URI MIME、EXIF、尺寸、压缩和宽高比保持。
- 正常响应：提取 URL、下载 PNG、转换 mask、调用 `process_classic`。
- 临时 URL 非 HTTPS、非允许域、重定向、超限、伪图片和解压炸弹均拒绝。
- 403 `AllocationQuota.FreeTierOnly`、欠费、429、5xx、超时、非法 JSON、缺少 URL 的错误映射。
- 缓存命中不发第二次云调用，且不占用日预算。
- 同一缓存键结果完全一致。
- 不同 `cloud_output_sha256` 产生不同 processing/stroke identity。
- 日限额和并发限制；多协程同键只调用一次。
- 日志、错误、audit 中没有 Key、Data URI 或签名 URL。
- `actual_provider`、request ID、prompt version、seed、cache hit 和输出哈希正确。
- 强度代理 warning 存在，不能把它标成模型置信度。

前端至少覆盖：

- capabilities 返回千问后下拉框显示“联网 · 计费”。
- 选择千问显示上传云端、计费和生成式风险提示。
- 未点击处理不发请求。
- 参数可见性与实际后端使用一致。
- 402/429/502/504 显示可读字符串，不出现 `[object Object]`。
- 取消等待文案说明可能已经产生云端调用。

真实烟雾测试单独放在显式脚本中，并要求同时设置：

```text
QWEN_CLOUD_ENABLED=true
QWEN_ALLOW_PAID_SMOKE_TEST=true
DASHSCOPE_API_KEY=...
```

该脚本只调用一张固定测试图，运行前打印模型、地域和“可能计费”确认；不纳入 pytest、CI 或应用启动流程。

## 13. 部署与密钥管理

### 本地开发

- PowerShell 环境变量可由现有启动脚本的子进程继承。
- `.env` 已在 `.gitignore`，但当前项目没有自动加载 dotenv；不能只创建 `.env` 就假定生效。要么由启动脚本显式加载，要么后续有意识地加入配置加载机制。
- 千问模式不要求启动 8010，但本地 detector 模式仍需要它。

### Docker

- 只把密钥注入 `stroke-review`，不要注入 `lineart-models`。
- 缓存目录如需持久化，给主应用单独命名卷。
- 不把 `.env` COPY 进镜像。
- 部署网络需允许访问配置地域的百炼 API 和动态 OSS 结果域名。

### 桌面包

- 默认禁用云模式。
- 不把 API Key、Base URL 或付费账户配置打包进 PyInstaller 产物。
- 缓存写入用户可写的数据目录，不能写安装目录或仓库目录。

## 14. 分阶段实施顺序

1. **配置与注册**：定义配置读取和 `QwenCloudPipeline`，仅在配置有效时注册。
2. **纯客户端层**：实现请求、错误归类、URL 下载和安全校验；全部 mock 测试。
3. **线图桥接**：抽取共用解码逻辑，接入 `process_classic`，验证画布与诊断图。
4. **身份与缓存**：加入缓存键、并发去重、输出哈希和云端 identity material。
5. **风控**：日限额、并发、超时、日志脱敏、Basic Auth/HTTPS 部署说明。
6. **前端**：动态选项、云端告知、参数可见性、错误和取消文案。
7. **文档与部署**：README、Compose、桌面包禁用策略和控制台操作清单。
8. **真实评估**：用少量、授权明确的测试图片比较候选模型；确认质量和成本后固定模型版本。

每一阶段先完成无付费 mock 测试。只有最后一步才允许一次显式真实调用。
