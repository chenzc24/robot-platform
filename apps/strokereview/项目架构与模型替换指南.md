# 项目架构与模型替换指南

本文面向后续接手开发、替换算法或训练新模型的工程人员。目标是让对方只替换“输入作品 → 结构化笔触”这一段，不需要改上传、审核、人工删除、拆分、补画、导出或网页布局。

## 1. 系统边界

系统接收 PNG、JPG 或 SVG，最终输出与机器人无关的二维几何笔触：

```text
浏览器上传
  → FastAPI 输入校验
  → ImageToStrokesPipeline（完整可替换边界）
      → 可选 LineArtDetectorAdapter（模型提取器可替换边界）
      → 二值图 / 骨架 / 图结构 / 连续笔触
  → ProcessResponse
  → 浏览器人工保留、删除、拆分、补画
  → strokes.json + audit.json
```

两个导出文件职责不同：

- `strokes.json`：面向下游，只包含当前 `keep` 笔触的 ID、正式绘制序号 `order`、点和闭合属性。数组与 `order` 均按低抬笔移动距离的确定性启发式结果排列，网页不显示编号。
- `audit.json`：保存算法、参数、全部状态、评分、原因、模型来源和人工操作结果。

人工审核发生在浏览器中，因此更换后端流水线不会影响删除、恢复、任意位置拆分和人工拖动补画功能。点击“重新处理”会重新调用流水线，当前页面中的人工修改会被新的算法结果替换。

## 3. 当前图片到笔触算法在哪里

### 3.1 清晰 PNG/JPG：classic

入口适配器是 `backend/app/pipelines/builtins.py` 的 `ClassicPipeline`，实际实现位于 `backend/app/classic_provider.py`。

当前顺序：

1. Pillow 读取，执行 EXIF 方向校正并转 RGB。
2. 根据 `detail_level` 限制处理分辨率。
3. OpenCV 灰度化、CLAHE、3×3 Gaussian Blur。
4. 根据平均亮度自动选择正/反极性，使用 Otsu 二值化。
5. scikit-image 删除小对象、填小孔洞；高清理强度时执行 3×3 闭运算。
6. OpenCV contrib `ximgproc.thinning` 使用 Zhang–Suen 得到单像素骨架。
7. Skan 将骨架拆成分支。
8. NetworkX 在交叉点以切线连续性为代价执行最小权匹配。
9. OpenCV Douglas–Peucker 简化折线。
10. SciPy `make_splprep` 平滑和重采样。
11. 按物理长度与线条置信度生成 keep/uncertain/discard。
12. 坐标按最长边归一化，生成稳定 ID 和输出文件。

### 3.2 普通照片：lineart / pidinet / hed

主后端适配器是 `LocalDetectorPipeline`，调用 `backend/app/local_model_provider.py`。

模型服务中的当前实现位于：

- `model-service/app/detectors/controlnet_aux.py`
- `model-service/app/detectors/registry.py`

过程：

1. 主后端把原图、模型 ID、检测分辨率发到 `http://127.0.0.1:8010/v1/extract`。
2. 模型服务懒加载 controlnet-aux 的 Lineart、PiDiNet 或 HED。
3. 模型返回灰度线图；主后端根据边框中值自动判断黑线白底或白线黑底。
4. 对置信图执行 Otsu 二值化。
5. 二值结果进入 `process_classic` 的骨架、分支组合、平滑、评分和输出阶段。
6. 服务不可用或模型报错时，自动回退到完整 classic，并写入 `local_model_fallback`。

重要现状：模型传入的 `line_mask` 当前不会再次运行 classic 的 `remove_small_objects`、`remove_small_holes` 和闭运算，只会在必要时缩放后直接骨架化。这是模型曲线容易出现许多小笔触的已知原因之一；替换模型时必须知道这一点。

### 3.3 SVG

入口适配器是 `SvgPipeline`，实现位于 `backend/app/svg_provider.py`。

- defusedxml 安全解析 XML。
- svgelements 解析 path、line、polyline、polygon、circle、ellipse、rect 和 transform。
- Bezier 与圆弧按误差自适应采样。
- stroke 路径直接转换为统一 Stroke；不先栅格化。
- 文字、滤镜、裁剪和嵌入/外部位图写入 warnings。

除非选择 Mock，SVG 会自动走 SVG 专用流水线，不受栅格 provider 下拉项影响。

## 4. 完整流水线替换接口

稳定接口在 `backend/app/pipelines/base.py`：

```python
class ImageToStrokesPipeline(Protocol):
    metadata: PipelineMetadata

    async def process(self, request: PipelineRequest) -> ProcessResponse:
        ...
```

`PipelineRequest` 提供：

- `content`：原始文件字节；
- `filename`、`content_type`；
- `input_kind`：`raster` 或 `svg`；
- `parameters`：已验证、也会进入审计文件的全部参数。

自定义实现必须返回现有 `ProcessResponse`。这样前端预览、审核和导出完全不需要修改。

### 4.1 最省事的做法：复制工作示例

复制 `backend/examples/custom_pipeline.py` 到例如：

```text
backend/app/partner_pipeline.py
```

修改类中的 `process`，然后设置：

```powershell
$env:STROKE_PIPELINE_PLUGINS="app.partner_pipeline:create_pipeline"
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1
```

插件 factory 可以返回一个 adapter，也可以返回 adapter 列表。注册表加载外部插件时允许覆盖同名实现。

### 4.2 不改变网页选项，直接替换现有算法

把插件的 metadata ID 设置成已有 ID：

```python
metadata = PipelineMetadata(
    id="classic",  # 也可以是 lineart / pidinet / hed
    label="伙伴的新流水线",
    description="完整替代当前图片到笔触流程",
    implementation="app.partner_pipeline.PartnerPipeline",
)
```

因为外部插件使用 `replace=True` 注册，FastAPI 路由、网页和导出代码都不用改。`audit.json.processing.actual_provider` 应写入能识别实际版本的名称。

### 4.3 新增一个可比较的 provider

使用新的 ID，例如 `partner_v2`。`/api/v1/capabilities` 会自动返回注册表元数据，前端启动后会自动把它加入算法下拉框，无需修改 React 的硬编码列表。

ID 规则：小写字母或数字开头，可包含小写字母、数字、下划线和连字符，最长 64 字符。

### 4.4 使用输出构造器

如果伙伴模型已经直接输出二维折线，推荐使用 `backend/app/pipelines/builder.py`：

```python
from app.pipelines import PipelineStroke, build_pipeline_response

candidates = [
    PipelineStroke(
        points=[(0.10, 0.20), (0.25, 0.32), (0.40, 0.35)],
        confidence=0.96,
        closed=False,
    )
]

return build_pipeline_response(
    request,
    actual_provider="partner_v2",
    source_width=source_width,
    source_height=source_height,
    strokes=candidates,
)
```

构造器负责：

- 画布和物理尺寸；
- SHA-256、processing ID、稳定 stroke ID；
- keep-only 正式文件；
- 完整 audit 字段；
- 统一 Pydantic 校验。

传入点必须已经位于本项目坐标系：最长边归一化、原点左上、x 向右、y 向下。横图通常 `canvas.width=1`，竖图通常 `canvas.height=1`。

### 4.5 自定义模型参数

`ProcessingParameters.provider_parameters` 是为插件预留的 JSON 对象。例如：

```json
{
  "provider": "partner_v2",
  "provider_parameters": {
    "checkpoint": "weights/v7.pt",
    "threshold": 0.42,
    "merge_radius_mm": 0.8
  }
}
```

内置 provider 不读取这些字段。自定义流水线可从 `request.parameters.provider_parameters` 使用它们，字段会完整进入 `audit.json`。如果要让普通用户在网页调整这些专用参数，再在 React 参数区增加对应控件即可；核心 API 无需改变。

## 5. 只替换线稿模型接口

如果伙伴只研究“照片 → 灰度线图”，希望继续使用当前骨架和笔触组合，使用 `model-service/app/detectors/base.py`：

```python
class LineArtDetectorAdapter(Protocol):
    metadata: DetectorMetadata

    @property
    def loaded(self) -> bool: ...

    def predict(self, image: PIL.Image.Image, resolution: int) -> PIL.Image.Image:
        ...
```

输出要求：

- 返回 Pillow 单通道灰度图，尺寸可以是模型工作尺寸；主后端会按需缩放。
- 可以是黑线白底或白线黑底，主后端会根据边框中值判断极性。
- 像素越能稳定区分线和背景越好；主后端随后执行全局 Otsu。
- `predict` 可以懒加载权重；`loaded` 不能触发下载。
- 加载或推理失败应抛出 `RuntimeError`，HTTP 层会返回 503，主后端会降级。

复制 `model-service/examples/custom_detector.py` 到例如：

```text
model-service/app/partner_detector.py
```

设置：

```powershell
$env:LINEART_DETECTOR_PLUGINS="app.partner_detector:create_detector"
```

若 metadata ID 使用 `lineart`、`pidinet` 或 `hed`，会直接覆盖现有模型，主后端和网页不需修改。如果使用新 ID，还需要在主后端注册同 ID 的完整流水线适配器，或把它加入伙伴自己的完整 pipeline 中。

当前 controlnet-aux 的代码封装只存在于 `ControlNetAuxDetectorAdapter`，API 路由没有模型名称 `if/elif`，因此可以替换 PyTorch、ONNX Runtime、OpenVINO、本地 HTTP 服务或其他实现。

## 6. 网页参数到底调了什么

以下是当前代码的实际行为，不是规划中的理想含义。

### 6.1 处理算法 `provider`

- `classic`：完整经典栅格流程。
- `lineart` / `pidinet` / `hed`：先用对应 CPU 模型生成线图，再走骨架流程。
- `mock`：固定测试输出。
- 外部 pipeline：由插件 metadata 自动加入。
- SVG 输入：除 Mock 外总是进入 SVG 专用流水线。

### 6.2 细节等级 `detail_level`，0–100

在 classic 栅格流程中同时影响：

1. 最大处理边长：

   ```text
   max_dimension = min(3072, 1024 + detail_level × 20)
   ```

   当前范围实际是 1024–3024 像素；原图更小时不会放大。

2. CLAHE 对比度强度：

   ```text
   clipLimit = 1.5 + detail_level / 50
   ```

   范围 1.5–3.5。

3. Douglas–Peucker 简化误差：

   ```text
   epsilon_px = 0.15 + (100 - detail_level) / 100 × 1.35
   ```

   细节越高，epsilon 越小，保留的折点越多。

在 Lineart/PiDiNet/HED 中还影响检测分辨率：

```text
raw = 256 + detail_level / 100 × 768
detect_resolution = raw 四舍五入到 64 的倍数，并限制在 256–1024
```

在 SVG 中影响曲线自适应采样容差，细节越高，采样越密。

### 6.3 清理强度 `cleanup_strength`，0–100

classic 先计算：

```text
pixels_per_mm = 处理图宽度像素 / 等比适配后的作品物理宽度
subresolution_area = round(
  (effective_resolution_mm × pixels_per_mm)²
  × (0.25 + cleanup_strength / 100)
)
```

- `remove_small_objects` 使用该面积阈值。
- `remove_small_holes` 使用 `0.75 × subresolution_area`。
- 当 `cleanup_strength >= 70` 时额外执行 3×3 椭圆核闭运算。

当前限制：模型线图路径会绕过上述三步，所以该滑块目前主要影响 classic，不会完整影响 Lineart/PiDiNet/HED。这一点应在后续统一 mask cleaner 时修正。

### 6.4 最小线长 `minimum_length_mm`

笔触组合完成后，按目标物理尺寸计算长度。当前风险分数：

```text
shortness = max(0, 1 - length_mm / minimum_length_mm)
low_confidence = max(0, 1 - confidence)
risk = clamp(0.65 × shortness + 0.35 × low_confidence, 0, 1)
```

决策：

- 长度 `< 0.5 × minimum_length_mm`：discard；
- 否则 risk `>= 0.7`：discard；
- 否则 risk `>= 0.4`：uncertain；
- 其他：keep。

长度小于阈值会记录 `too_short_isolated`，置信度小于 0.35 会记录 `low_confidence`。

当前实现是在完整笔触层判断，不是对骨架短边做拓扑保护；连接重要结构的短分支规则仍需增强。

### 6.5 平滑程度 `smoothing`，0–100

折线简化后，若至少有 4 个点且 smoothing 不为 0，调用 SciPy B 样条：

```text
s = smoothing / 100 × 点数 × 0.04
```

- 开放笔触保留原始首尾点。
- 闭合笔触使用 periodic 边界。
- 重采样数量约为每 2 像素一个点，最低不低于输入点数，最高 4096。
- 样条失败时保留简化后的原折线。

平滑只改变每条已组合笔触的形状，不会把两条断开的笔触连接起来。

### 6.6 物理画布 `target_width_mm` / `target_height_mm`

- 定义最终纸张/画布的物理宽高；作品保持原比例、居中适配，不拉伸。
- 决定 `mm_per_pixel = 等比适配后的作品物理宽度 / 处理图宽度`。
- 影响最小线长判断、人工笔触长度和有效分辨率换算。
- 会把居中留白反映到 normalized 坐标；画布最长物理边归一化为 1。
- 旧 API 请求省略 `target_height_mm` 时保留旧行为，按作品比例推导高度。

### 6.7 笔宽 `pen_width_mm`

网页为 classic、Lineart、PiDiNet、HED 和千问栅格流程显示此参数，默认 0.5 mm。它用于按真实直径预览笔触，并检测同方向、长距离且中心线落入一个笔径内的近重复平行笔触。冗余候选只会降为可恢复的 `uncertain`，不会被永久裁剪或合并；SVG 和 Mock 当前不使用，因此网页会隐藏该输入框。

### 6.8 有效分辨率 `effective_resolution_mm`

- 参与 classic 的小对象/小孔洞面积计算。
- 参与 SVG 自适应采样容差：

  ```text
  tolerance_svg = max(
    0.05,
    effective_resolution_mm / SVG等比适配后的毫米每源单位
    × (1.5 - detail_level / 100)
  )
  ```

当前尚未单独生成 `below_effective_resolution` 原因，也没有统一应用到模型 mask。

目前网页没有单独显示此输入框，默认 0.25 mm。

### 6.9 插件参数 `provider_parameters`

内置算法不使用。它是自定义流水线的自由 JSON 配置区，会进入审计文件，避免伙伴每增加一个模型参数都要改核心 Pydantic 契约。

## 7. 运行环境和模型要求

### 7.1 本地开发

- Windows PowerShell 5.1 或更新版本；
- `uv 0.11.x`；
- Node.js LTS 和 npm；
- 不要求 Docker、Git 或 GPU。

主后端：

- Python `>=3.12,<3.14`；当前本机由 uv 使用 3.13。
- OpenCV contrib、scikit-image、Skan、SciPy、NetworkX、svgelements。

模型服务：

- Python `>=3.12,<3.13`，固定 3.12。
- CPU 版 PyTorch、controlnet-aux、Pillow。
- 推荐至少 16 GB 内存，并为 Python 环境和权重缓存预留数 GB 磁盘。
- 首次使用内置模型需要访问 Hugging Face；之后读取本机缓存。

端口：

- 5173：Vite 网页；
- 8000：主 FastAPI；
- 8010：本地模型服务。

一键启动：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1
```

只用 classic/SVG、完全不启动深度模型：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1 -SkipModels
```

### 7.2 新模型的工程要求

完整流水线模型必须：

- 接收 `PipelineRequest`，返回通过 Pydantic 校验的 `ProcessResponse`；
- 输出至少两个点的笔触；
- 坐标有限、在约定画布范围内；
- 同一输入和参数应保持确定性排序、坐标和 ID；
- 不把模型调试字段塞入正式 `strokes.json`；
- 将版本、权重、阈值和警告写入 audit processing、parameters 或 warnings；
- 明确权重许可证、缓存位置、网络需求、CPU/GPU需求和失败降级。

只替换 detector 时，应输出稳定灰度线图，并避免把纹理全部当作边缘。若使用 GPU，可在自定义 adapter 内决定设备；现有服务响应的 `device` 字段和部署资源声明也应同步调整。

## 8. 环境变量

```text
APP_ACCESS_USERNAME / APP_ACCESS_PASSWORD  最小 Basic Auth，必须配合 HTTPS
MAX_UPLOAD_MB                              上传上限，默认 25
LINEART_LOCAL_SERVICE_URL                 主后端访问模型服务的地址
LINEART_LOCAL_TIMEOUT_SECONDS             模型调用超时，默认 300 秒
LINEART_MODEL_REPOSITORY                  内置 controlnet-aux 权重仓库
STROKE_PIPELINE_PLUGINS                   完整流水线 factory，逗号分隔
LINEART_DETECTOR_PLUGINS                  detector factory，逗号分隔
```

插件变量格式：

```text
package.module:factory,another.module:create_adapter
```

本地 PowerShell 环境变量会被 `start-dev.ps1` 启动的子进程继承。Docker Compose 也已预留这两个变量；自定义代码必须被复制进镜像或作为安装依赖提供。

## 9. API 和契约

- `GET /api/health`：主服务健康状态。
- `GET /api/v1/capabilities`：当前已注册 provider 及 metadata；前端动态生成下拉框。
- `POST /api/v1/process`：稳定上传入口。
- `GET /api/v1/schema/strokes.json`：正式契约 JSON Schema。
- `GET /api/v1/schema/audit.json`：审计契约 JSON Schema。
- 模型服务 `GET /api/health`：detector、实现、仓库和懒加载状态。
- 模型服务 `POST /v1/extract`：稳定 RGB 图片到灰度线图边界。

## 11. 当前已知限制

- 模型 mask 尚未复用 classic 的完整形态学清理，模型输出可能产生大量短笔触。
- 骨架端点只在现有规则下配对，尚未做按毫米尺度的小断口桥接。
- 笔宽重合目前只做保守的整条近重复判断，尚未裁剪局部重合或自动合并中线。
- SVG 文字、滤镜、裁剪和嵌入位图尚未转换为笔触。
- 人工修改仅存在于当前浏览器页面，刷新或重新处理后不会自动恢复。
- 内置模型权重许可标记不够明确，仅按当前非商业实验使用；商业化前必须重新审核。
- Docker 文件已预留插件和模型服务，但本机没有 Docker，仍未进行本机构建验证。

接口抽象的目的不是隐藏这些限制，而是让伙伴能够在不破坏产品闭环的情况下，针对这些问题替换整条流水线或其中的模型提取器。
